# 两步验证(2FA)· TOTP / 恢复码 / 邮箱备用

玩家与管理员账号的两步验证,基于 TOTP(RFC 6238,验证器 App 如 Google Authenticator / Aegis / 1Password)。

## 玩家侧(控制台「两步验证」卡片)

- **开启**:控制台 → 两步验证 → 开启 → 验证器扫码(或手动输入密钥)→ 输入 6 位验证码确认 → 展示 **8 个一次性恢复码**(仅此一次,请立即保存)
- **登录**:密码通过后需输入验证码;验证器丢失可用恢复码(形如 `XXXX-XXXX`,单次有效)或**邮箱备用验证码**(登录卡片点「无法使用验证器?」,发到绑定邮箱,5 分钟有效,3 次/5 分钟)
- **停用**:控制台 → 两步验证 → 停用,需当前密码 + 验证码(验证器码或恢复码)

## 管理员强制 2FA

后台「系统设置 → 账号安全 → 管理员强制两步验证」开启后:名单内管理员未绑定 2FA 时登录,会被引导到强制绑定页(扫码 → 验证码 → 恢复码 → 完成登录),不绑定无法进入后台。

## 安全设计

| 项 | 说明 |
|---|---|
| 密钥存储 | dp_user_2fa.secret,Base32;验证 ±1 窗口(±30s 时钟容错) |
| 恢复码 | 库中只存 bcrypt 哈希(JSON 数组),使用即删除 |
| 邮箱备用码 | 内存态 5 分钟,不落库,与注册验证码池隔离 |
| 登录挑战(challenge) | 密码通过后签发的**服务端内存凭据**,5 分钟;仅能用于 2FA 验证/强制绑定,不授予任何会话权限(非 JWT) |
| 防爆破 | 2FA 验证连错 5 次锁 15 分钟;登录/验证接口各有 IP 限流(登录 5/min、验证 10/min、邮箱码 3/5min) |
| 停用保护 | 必须同时提供密码 + 验证码,防止盗号后单点关闭 |

## 部署与运维

- 新表 `dp_user_2fa`(V13),Flyway 自动迁移,零配置
- 邮箱备用码依赖 SMTP 已配置(未配置时进入日志模式,码仅打印在服务端日志,生产务必配置 SMTP)
- 相关审计:`settings_security`(强制开关变更);验证失败不写审计(只记应用日志)
